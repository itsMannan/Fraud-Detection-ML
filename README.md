# Intelligent Credit Card Fraud Detection and Risk Scoring

Production-style **Python** pipeline that finds fraudulent credit-card transactions on the public ULB dataset, then turns the model probability into a **0–100 risk score** with graduated actions.

The positive class is only **0.17%** of traffic. Accuracy is therefore ignored. The system is scored on **precision, recall, F1, and PR-AUC**.

## Why accuracy is the wrong metric

| Always predict “legitimate” | Catch fraud? | Accuracy |
|---|---|---|
| 284,315 / 284,807 correct | **0 / 492** | **99.83%** |

A dummy model looks excellent and protects nobody. This repo never reports accuracy as a success metric.

## Dataset

| | |
|---|---|
| Source | [ULB credit-card fraud](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud) (TensorFlow public mirror) |
| Rows | 284,807 transactions |
| Fraud | 492 (0.172%) |
| Features | `Time`, PCA components `V1`–`V28`, `Amount`, label `Class` |

The file `creditcard-selected-columns.csv` in the repo root is an **empty placeholder** (header `Time,V1,…,V9` only — no `Amount`, no `Class`, no rows). `train.py` detects that and **auto-downloads** the full public CSV to `data/creditcard.csv` (~144 MB, gitignored).

## Success targets

| Metric | Target | Meaning |
|---|---|---|
| Precision | 0.75–0.85 | Of fraud **flags**, how many were fraud? (customer friction) |
| Recall | 0.80–0.90 | Of actual frauds, how many did we catch? (financial loss) |
| F1 | 0.75–0.85 | Harmonic mean of precision and recall |
| PR-AUC | **0.80+** | Ranking quality under extreme imbalance (primary) |

Hold-out scores and plots are generated by training (see **Results** below).

## Pipeline (what `train.py` actually does)

1. **Load and explore** — class counts, missingness, amount stats.
2. **Stratified 70 / 10 / 20 split** (train / validation / test) so each split keeps the 0.17% fraud rate. The test set is untouched until the end.
3. **Feature engineering (train-fit only)**
   - `Amount_log = log1p(Amount)`
   - `Amount_zscore` and `Amount_to_mean` using **train** mean/std
   - `Hour`, `Hour_sin`, `Hour_cos`, `Is_night` from `Time`
4. **StandardScaler** fitted on train, applied to val/test.
5. **Imbalance handling**
   - **SMOTE on train only** (minority → 10% of majority) for logistic regression
   - `class_weight='balanced_subsample'` for Random Forest
   - `scale_pos_weight = n_legit / n_fraud` for XGBoost and LightGBM
6. **Models** — Logistic Regression, Random Forest, XGBoost, LightGBM, and a soft-vote ensemble of the tree models. Boosting uses **PR-AUC early stopping** on the validation split (not the test set).
7. **Threshold** — F1-optimal cutoff is chosen on **validation**, then frozen for test. Default 0.5 is not used blindly.
8. **Hold-out evaluation** — precision, recall, F1, PR-AUC, ROC-AUC, specificity, balanced accuracy, MCC, confusion matrix.
9. **Risk scores** — `risk = P(fraud) × 100` with bands below, plus a composite score that also uses amount unusualness and night-time flags.
10. **Stratified 5-fold CV** on a training subsample (comparison, not model selection).

SMOTE is never applied to validation or test (that would leak labels and inflate scores).

## Risk bands

| Score | Band | Action |
|---|---|---|
| 0–30 | Low | Approve immediately |
| 30–60 | Medium | Manual review recommended |
| 60–80 | High | Block and notify the customer |
| 80–100 | Critical | Block and escalate to the fraud team |

Composite score (no geolocation in this dataset):

```
0.70 × P(fraud) + 0.20 × amount_deviation + 0.10 × unusual_time
```

## Design choices (vs. common mistakes)

| Mistake | What this repo does instead |
|---|---|
| Report 99%+ accuracy | Precision / recall / F1 / **PR-AUC** |
| SMOTE the whole CSV then split | Split first; SMOTE **train only** |
| Random split | `stratify=y` on every split and on CV |
| Tune the threshold on the test set | Tune on validation, freeze, then test |
| Early-stop XGBoost on the test set | Early-stop on validation PR-AUC |
| Default 0.5 cutoff | F1-optimal validation threshold |
| 1:1 SMOTE (~450k rows) | Mild SMOTE (10% ratio) + class weights on trees |
| Scale with full-data statistics | `StandardScaler` and amount z-scores fit on train |

## Retrain / monitor

In production, track monthly precision, recall, F1, and PR-AUC. Retrain when any of them drops more than ~5% or when feature distributions drift. The saved bundle is `artifacts/models/champion_bundle.joblib` (engineer + scaler + model + threshold).
